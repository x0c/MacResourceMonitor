# 产品契约

覆盖：任何用户看得见的行为（菜单栏图标/表、人话名、整机占用、结束、开机自启、网速与网络表等）。不覆盖：工程构建/发版步骤（见分发知识库与 OPERATIONS_GUIDE）；跨产品菜单栏生命周期见全局 macOS 应用开发指南。

本文件是用户可见行为的唯一权威源。全局身份识别背景见 `~/.config/agentsync/docs/MAC_PROCESS_IDENTITY_KNOWLEDGE_BASE.md`（只读，冲突时以本文为准）。

## 产品是什么

卡的时候一眼看到是谁占满这台电脑的 CPU，并立刻结束。名字：**CPU Killer**。不要再换成谜语名。

**【裁定 2026-08-30】** 这是**菜单栏应用**。程序坞没有图标，没有桌面进程表工作区。日常界面是点菜单栏图标展开的那张表。不是 Stats（Stats 只看整机小数、行上不能结束）。

**【裁定 2026-09-05】** **禁止隐藏菜单栏图标**（图标即唯一主入口）。跨产品登录静默 / 隐藏资格 / 恢复面规则 → `~/.config/agentsync/docs/MACOS_APP_DEVELOPMENT_GUIDE.md`。进程表仍是点外关闭的唤出浮层，禁止改成常驻桌面工作区；设置窗是配置面，不是「藏图标后的恢复面」。

## 第一眼必须看到的表

初始打开的是 CPU / 内存表，列只有这些，顺序固定：

1. 应用图标
2. 人能认的名字
3. 占整机算力的百分比
4. 占物理内存的百分比
5. 结束

**【裁定 2026-09-04】** 菜单栏图标里的双环和上下行网速块都是列表入口：点击双环时展示上述 CPU / 内存表；点击上行或下行读数时，展示网络占用表。网络表每次打开都默认按**下行（Download）**从高到低排，不随点击的是上行或下行而改变。网络表沿用同一块浮层、顶栏、刷新开关、图标、名字和结束符号的样式与安全边界，只把两列占用改为**上行**、**下行**。点击上行或下行表头时也只按对应方向从高到低排，没有升序。两张表的刷新开关独立冻结各自名单；收起浮层时两张名单都停止更新，菜单栏双环与网速读数继续独立刷新。禁止把网络占用塞回 CPU / 内存表、另开桌面窗口，或把任一入口改成右键菜单。

**【裁定 2026-09-04】** 网络表与菜单栏网速必须**同一拍**：列表每次展示的上/下行速率和菜单栏同样按约一秒的节奏更新，不能出现菜单栏已经变化、网络表隔数秒才跳一次的割裂感。刷新开关关闭后只冻结网络表名单；菜单栏读数仍按原节奏更新。

**【裁定 2026-09-04】** 打开网络表必须立刻有内容：保留最近一帧可用的网络名单，首次采样尚未完成时展示这帧而不是白屏或空白列表；若还没有任何可用名单，显示一条克制的“正在读取网络占用”说明，不能留下无内容的大白块。

**【裁定 2026-09-05】** 网络表的速率列必须和 CPU / 内存表使用同一套行级排版：正文统一 12pt 系统字体，数值使用等宽数字，行高和列宽不因加入 `KB/s`、`MB/s` 或 `GB/s` 单位而放大。上行、下行都要按量值使用同一套低到高的颜色层级：无样本或低于 1 KB/s 为次要色，达到 1 KB/s 为主色，达到 1 MB/s 为橙色，达到 10 MB/s 为红色。阈值只能集中在共享的展示规则中，不能让网络表另起一套只判断“是否大于 0”的颜色逻辑；这保证网络表和 CPU / 内存表一眼属于同一张表。

**【裁定 2026-09-05 · 补】** 只把整段 `47 KB/s` 设成同一 12pt **不够**：大写单位字母比 `%` 更高，整格会显成比 CPU / 内存百分比**大一号**。速率列必须拆开排：数字仍与百分比同为 12pt 等宽数字；`KB/s` / `MB/s` / `GB/s` 用更小一号（约 10pt）紧跟数字，颜色跟数字同一档。禁止为了省事整段同号，也禁止只靠缩小整段数字去迁就单位。

**【裁定 2026-09-05】** 网络表名单禁止秒级闪烁：某一拍上下行都为 0 时，**不得立刻把该责任进程整行踢出**。刚有过流量的行至少再留约 **5 秒**，期间显示 `0 KB/s`（走次要色），排到活跃行后面；满 5 秒仍无流量再消失。进程本身已不在责任名单里时立刻移除，不要留幽灵行。禁止为了“列表永远只有正在跑流量的进程”而让 Chrome 这类还开着、只是某一秒没包的应用在表里进进出出。

列表永远是平的。禁止进程树、禁止「点开看孩子」、禁止展开。同一桌面应用底下的助手折进该应用那一行并加总，看不见、点不开。

默认按 CPU 从高到低排。近乎空闲的行默认不占位置，避免一打开全是 0.0%。监视器自己不要变成前几名占用者。

### 表头不许巨大

**【裁定 2026-08-30】** 点开后第一行数据必须贴着顶栏。禁止再出现「上面一大块空白、表头掉在半截」的标题栏留白。顶栏只留一行：刷新开关 + 列名。列名是细字，不是第二套大标题。结束是安静的关闭符号，不要每行一个描边「End」网页按钮。关闭符号只有鼠标压在它上面才变红。

**【裁定 2026-08-30】** CPU / 内存列表头直接写出整机汇总，格式如 `CPU 88.8%`、`Mem 68.8%`（中文内存列为 `内存 68.8%`）。数字与菜单栏双环同一口径、同一拍：CPU 是各行人话行加总（上限 100%），内存读系统级物理占用，**禁止把各行内存相加**。汇总跟双环一起刷新；关掉刷新开关只冻结名单，表头数字仍更新。不要另起一行、不要在刷新开关旁再堆一套大数字。

**【裁定 2026-08-30】** 点 CPU 列或内存列，名单改按该列**从高到低**排。没有从低到高，再点同一列也不翻转。默认仍是 CPU 从高到低。名字列、图标列、结束列不可点来排序。当前排序的那一列字更实，另一列保持次要色。这次点开记住即可，不必写进设置、下次打开仍从 CPU 从高到低开始。

**【裁定 2026-09-01】** 名字列必须让常见桌面短名一眼读完：Google Chrome、Activity Monitor、Microsoft Edge 在正文 12pt 下不得出现省略号。336pt 面板在系统「始终显示滚动条」时名字列只剩约 80pt，会把 Chrome 中间省略成 `Goog...rome`，禁止再出现。不要只改省略方向、不要整表缩字、不要折成两行、不要按最长包名把整张表撑开。三层办法：

1. 面板略加宽、占用列略收，**常显滚动条之后**名字列仍够上述短名。
2. 仍放不下的名字只缩这一行（下限约 10pt）；短名保持 12pt。
3. 还是放不下才省略：无空格且含 `.` 的反向域名用**前缀省略**，露出末段（`...TimeMachine`）；人话名用**后缀省略**，露出开头（`Google Chrome Hel...`）。禁止再对两类名字统一用中间省略。鼠标停在名字上仍浮出全名。

## 刷新开关

**【裁定 2026-08-30】** 展开的表顶有一个刷新开关，默认开。

- **开**：表在眼前时按 1–2 秒一拍更新。
- **关**：名单冻结，方便对准一行去结束，不被跳动打乱。
- **收起这块**：**立刻停止采样**，不管开关是开是关。不要在背后一直刷。
- 关掉再展开：若开关仍开，立刻采一拍并继续；若开关关，只展示上次冻结的名单（若还没有名单，采一拍再停）。
- 开关要记住。不要再做第二个开关到设置里。

## 人话名与折行（本机已验证，禁止推翻）

短名属于解释器家族（node / Python / Java / Ruby / `agent` 被改成 `MainThread` 这类）时，主标题用启动参数里第一个像用户意图的词。副信息不单独占列。

| 实际是 | 必须显示成 | 结束这一行会怎样 |
|---|---|---|
| ChatGPT 桌面、电脑操控（`cua_node`）、以及它拉起的 `mcp-server-memory` | **一行 ChatGPT** | 结束这一家（电脑操控一起没）。这是预期。 |
| 每个 Cursor 命令行助手（不是 Cursor.app；父进程是 tmux） | **各自一行** | 只杀那一只，不杀别的助手，不杀 Cursor 窗口 |
| `pi` | **单独一行 pi** | 只结束这一只 |
| Corral（解释器短名常是 Python；本机常见是 Homebrew 自带的 Python.app） | **Corral**，不是 Python | 结束 Corral 自己；**不杀** tmux 保活里的其它助手 |
| `mcp-server-memory` | **不占行**，跟父家 | 随父家一起结束 |

从终端、iTerm、Cursor 里拉起的独立命令单独占行，不折进 Cursor.app。Cursor 的图形窗口仍是单独一行。Homebrew 那种 Python.app **不是**桌面应用家，禁止把 Corral 显示成 Python。

`mcp-server-memory` 永远不单独占行。

## 占用怎么报

- **CPU：占整机逻辑核之和的百分比，上限 100%。** 本机 8 核时，活动监视器里 80% 的单线程 ≈ 本表 10%。不要做成活动监视器那种可超 100% 的单核累加。
- **内存：占这台机器物理内存的百分比**，不是 GB，不是 resident。列表每行使用物理占用账本；整机内存指标必须读取系统级物理内存统计，禁止把各进程行相加，因为共享页会被重复计算。整机百分比对齐活动监视器底部「已用内存」（应用 + 系统占住的 + 压缩），**不含文件缓存**。这台 16GB 刚开机、日常小工具都在时到六十多是正常水位，不是泄漏。禁止把文件缓存算进内环（会接近满环），禁止用系统「空闲百分比」去对拍这个数。吃紧与否看内存压力和交换盘，不看空闲页是不是接近 0。
- **刷新开关：只控制进程列表是否继续更新。** 关闭后列表保持当前快照，方便连续点击结束；菜单栏双环和表头汇总仍必须继续更新。面板收起时不更新进程列表，双环保持独立刷新。

## 结束

- 行上直接结束。菜单栏点开就是为了这一下。
- 只结束**当前用户**的进程。别人的只展示，结束符号置灰、点不了。
- 系统进程（窗口服务、启动服务、内核相关等）**禁止一键杀**，结束符号同样置灰、点不了。若仍被请求结束，允许失败，界面显示失败，不许假装成功。系统进程即使启动参数看起来像独立工具名，也不得当成可结束的工具行。
- 桌面应用那一行：先正常结束再强制结束这一家。
- 解释器独立行：先礼貌结束再强制结束那一个进程。
- 结束失败要让用户看见，不要静默当成功。
- **【裁定 2026-08-30】** 结束符号默认是安静的灰色。**只有鼠标压在可结束的那个符号上才变红。** 鼠标在这一行其它位置、键盘焦点、点开时被默认选中，都不许变红。不能结束的行仍画出关闭符号，但是置灰、点不了——不要藏掉。
- **【裁定 2026-08-30】** 鼠标停在某一行的结束符号上时，**这一行钉在原位**，刷新不得把它顶走、换位或换成别的进程。对准结束再点下去时，名单跳动不得误杀另一行。占用数字可以原位更新，人不能换、位置不能动。鼠标离开结束符号后，这一行重新参与排序。若悬停期间这一行已经没了，立刻解除钉死，不要把结束点到刚顶上来的另一行。刷新开关关掉时名单本就不跳，这条不额外做事。菜单栏双环和表头汇总不受影响，继续刷新。钉死只针对结束符号，停在名字或占用数字上名单照常跳。

## 菜单栏

- **左键**：打开这张表。**表必须出现在菜单栏图标正下方**（水平以该图标为中心，贴在菜单栏底下）。点面板外立刻关掉这块。点面板内、点本菜单栏图标不关。
- **【裁定 2026-08-30】** 拿不到图标位置时先等图标就绪再打开，禁止把空坐标、屏幕底部的假位置当成锚点——那样会掉到屏幕左下角。不要为了验收自动弹出而把表甩到角落。
- **右键**：开机自启、打开主窗口（设置窗）、设置、检查更新、退出。禁止把系统菜单常挂在状态项上（挂了左键就变成弹菜单）。左键永远只开进程表，不弹菜单。
- **【裁定 2026-09-03】右键网速开关**：右键菜单必须提供「显示网速」勾选项，默认开。关闭时只隐藏菜单栏中的两行网速读数；双环、左键打开进程表、网速取样及其它右键菜单项都不受影响。用户选择必须在下次打开应用时保留。
- **【裁定 2026-09-05】菜单栏入口固定顺序**：双环与网速已经是两个独立的菜单栏状态项，因此不再提供「菜单栏布局」选项，也不保存左右布局偏好。菜单栏固定为「圆环在左，网速在右」；两项各自保留独立的左键入口和右键菜单，不因隐藏网速读数而改变圆环的位置。
- **开机自启**在右键菜单和恢复窗里都要有，**默认关**，必须用户自己打开。菜单勾选是三态：开 / 关 / 待批准。待批准显示成中间态、**不是开**，并提供去系统设置 › 通用 › 登录项。
- **禁止隐藏菜单栏图标 / 登录静默 / 检查更新入口 / 二次启动防呆**：跨产品权威见 `~/.config/agentsync/docs/MACOS_APP_DEVELOPMENT_GUIDE.md`【裁定 2026-09-05 / 2026-09-07】。本产品：无 Hide/Show 项；启动强制图标可见并清掉历史 `menuBar.iconVisible`；登录拉起走 MacKit `LoginLaunchDetector` + `MenuBarReopenPolicy`；菜单栏即主入口——首次启动不出窗，就绪后约 60 秒内再次打开须出设置窗（`menubarIsPrimaryEntry`）；公开版「检查更新…」走 Sparkle，**右键与设置窗都必须有**，禁止改网页下载。
- **打开主窗口 / 设置窗**：出示带标题栏的设置窗（不是进程表）。里面有：应用仍在工作、开机自启、**检查更新**（与右键对等）。关掉这一窗 ≠ 退出。
- **【裁定 2026-09-03】菜单栏网速**：菜单栏在双环旁显示一个**紧凑**的两行实时网速块：**上面一行永远是上行并显示 `↑`，下面一行永远是下行并显示 `↓`**。这一方向映射与读数大小、字号、单位、对齐和刷新状态完全无关，禁止改换、镜像或凭视觉布局重新猜测。**【排错 2026-09-04】** 若行位置颠倒，必须修正纵向绘制坐标的上下边界，禁止交换上/下行读数或交换箭头来掩盖；坐标轴向上增长时，上行的可见字形锚在布局框的高边，下行锚在低边。双环与网速块必须使用菜单栏中间同一个 17pt 高布局框（上下各留 2.5pt），作为对原尺寸约 6% 的整体放大；禁止单独放大其中一项。以实际可见字形而不是行框计算时，网速块与双环的垂直中线必须像素级重合；字体天然较矮时，双环上下留出的空白必须对称，禁止出现文字贴近下边缘、上边却悬空的假对齐。禁止为了填齐网速块而继续放大双环、让任一部分偏离这个布局框，或让小双环挤在过高的读数块中间。两行单位共用同一条右侧边线；每行数字必须贴在本行单位左侧，只有固定小间隔，**禁止**把上下两行数字强行对成同一条右边线。单位放在数字右侧、上下箭头左侧，并在上下两行都完整显示；两支方向箭头位于最右列并上下对齐。固定顺序是「数字 → 单位 → 箭头」，禁止单位拉伸、旋转、跨行或挂到某一行末尾。**【裁定 2026-09-04】速度对比排版**：上下行中原始速度较大的一行，数字与单位必须同步使用较大的字体；另一行数字与单位使用较小字体，形成克制的速度对比。方向箭头始终使用同一基准字体，不随速度变化而改变大小或位置。上下行相等、任一行暂时无读数时，两行数字与单位恢复为相同大小，禁止制造虚假的主次。无论大小关系如何切换，上行整行实际可见字形的上边缘必须贴齐共同布局框上缘，下行整行实际可见字形的下边缘必须贴齐共同布局框下缘；由此保持整块与双环同高同中线。单位右边线、最右箭头列及垂直中线不得跳动；数字随本行单位贴合，不要求也不得形成跨行右边线。读数使用清晰、克制且不过粗的系统等宽数字字体；两行之间不留额外间隙，禁止为了放大字符再压缩行距或让可见字形越出共同的 17pt 布局框。读数只显示整数，不显示小数位。每次刷新按上下行中量级更大的那个选择单位，两行必须使用完全相同的 `KB/s`、`MB/s` 或 `GB/s`；较小读数不足一个共同单位时显示 `<1`，禁止为了凑整数夸大成 `1`，也禁止只显示 `K`、`M`、`G` 等含义不明的缩写。网速必须自动识别当前真正承载外网流量的网卡；切换 Wi-Fi、以太网或 VPN 时不能把多个接口粗暴相加，也不能继续显示旧网卡的残留读数。具体的无网络状态、平滑规则及与双环的最终尺寸，须在实现前按本条继续定稿。
- **【裁定 2026-09-05】网速刷新稳定且横向紧凑**：刷新只替换上下行读数的内容，不得改变网速状态项的外框宽度、单位右边线、最右箭头列或它在菜单栏中的锚点——禁止为了跟当前字形省宽度而在刷新时动态改外框（那会左右抖动）。固定排版框必须按**紧凑上限**预留：数字列最多三位（`999`），单位列取 `KB/s` / `MB/s` / `GB/s` 中最宽者；**禁止**再常驻预留四位 `9999` 或只按 `GB/s` 估宽，以免日常两位数读数（如 `22 KB/s`）左侧重新出现一大段空白（**【回归 2026-09-05】** 用户截图确认该空白会随「防抖动」改回四位预留而复发）。读数格式本身不得吐出四位及以上整数：当前单位下将满 `1000` 时改升到下一档单位，这样固定框够用且日常不浪费。短于三位的空位只能留在数字列左侧；数字仍贴本行单位左侧，`↑` / `↓` 始终贴固定最右列。禁止拿掉完整单位或箭头、改变「数字 → 单位 → 箭头」顺序来省宽度。
- **【裁定 2026-09-04】数字与单位间隔**：数字贴在本行单位左侧，但必须保留固定 2pt 的细小阅读间隔。该间隔是排版规则，不可拿来补偿对齐；禁止数字与单位完全粘连。
- 禁止用 SwiftUI `MenuBarExtra` 当左键主路径。
- 退出只走右键「退出」。系统顺手退出必须拦住；正在安装更新时放行。最后一扇窗关上也不退出。

## 菜单栏图标设计方向

**【确认方向 2026-08-30】** 用户确认将一个圆润、同心的双环模板图标作为接入方向，借鉴活动环的“环形进度”阅读方式，但不复刻 Apple 的具体图形：

- 外环表示整机 CPU 占用，内环表示物理内存占用。
- 外环沿用现有整机 CPU 的显示口径，但不受列表冻结影响；关闭刷新后继续取得新 CPU 数据，只是不把新数据写入进程列表。
- 外环只接受前后两次有效 CPU 样本；进程刚出现、刚退出或系统瞬时读不到样本时保留上一帧，不能闪成空环。真实的 0% CPU 仍显示为空环。
- 内环使用系统级物理内存占用百分比，和列表中各进程行的占用值独立计算；不能把列表行相加后当作整机内存，否则共享内存会让内环错误地提前满环。
- 每个环都由已满足的进度弧段和未满足的轨道组成；两端保持圆润，双环间距稳定，在 16–20 pt 菜单栏尺寸仍要能一眼分辨。
- 预览稿用黑色表示已满足、灰色表示未满足，直观看出两种占用状态；这只是探索稿的视觉表达。
- 正式菜单栏模板资源仍遵守“透明背景 + 纯黑主体”的规则：未满足轨道用纯黑的较低不透明度表达，让系统负责浅色/深色菜单栏着色，不把固定灰色像素写进资源。
- 不放文字、数字、方形底板、阴影或额外留白；生产实现使用确定性绘制，探索稿本身不作为最终资源文件。

## 应用图标

**【裁定 2026-08-30】** 应用图标的主体必须是用户一眼能认出的 **CPU / 处理器芯片**。探索时可以改变芯片的几何化程度、材质、色彩、视角和内部细节，但不能把主图换成日蚀、工具、按钮、动物或其他控制物件；不能依靠文字解释“CPU Killer”。应用图标与菜单栏双环模板仍是两套资产，双环不替代 CPU 主体。

**【排查 2026-08-30】** 进程表每一行的图标是向系统要「这个应用包现在的图」，不是监视器自己画的，也不是菜单栏双环。换了应用图标之后，表里（包括 CPU Killer 自己那一行）仍可能显示上一版，例如粉底黑叉。这不是图标没装进包，也不是菜单栏模板错了。禁止为了让自己那一行立刻变新就改成读监视器内置图，或去清系统图标仓库。覆盖安装必须先删掉整个应用再整包复制；只往原文件夹里覆盖时，系统更容易继续吐旧图。核四处：安装包里的图、系统登记、Finder、进程表；进程表要退出监视器再打开才算数。
